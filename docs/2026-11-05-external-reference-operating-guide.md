# 판타지 마스터즈 카드DB 운영 기준 보강 — 외부 원작 참고자료

- 작성일: 2026-11-05
- 대상: `dragonslayers-k/T` 카드DB 작업 브랜치
- 적용 기준: DB29는 불변 기준점. DB30 미발행, `main` 미병합.
- 목적: 나무위키와 개인 원작 가이드 등 외부 참고자료를 카드별 검토 및 향후 APK 규칙 구현에 체계적으로 연결한다.
- 상태: 참고자료 등록 및 검토 절차 확정. 개별 카드 효과는 카드 원문·실행 검증 전까지 자동 확정하지 않는다.

## 2. 나무위키 본문 및 하위 링크 순회 기준

확인 대상 섹션은 3.4 속성, 3.5 종족과 소속, 3.6 카드와 속성별 하위 카드 문서(암흑/불/물/숲/금속/대지/빛/무속성)이다. 각 문서 안의 카드·스킬·게임시스템 링크도 따라가며 자료를 수집한다.

링크 검토는 다음 필드를 포함한 자료 인덱스로 남긴다.

- `source_id`, `source_url`, `source_title`, `source_type`
- `parent_source_id`, `link_label`, `linked_url` (내부 링크 계보 보존)
- `topic` (attribute / race / faction / card / skill / mechanic / strategy)
- `card_id` 또는 `card_name` (식별 확정 시)
- `source_version_or_date`, `retrieved_at`
- `evidence_excerpt` (짧은 근거 발췌), `claims`
- `evidence_status`: observed / corroborated / conflict / unreadable / inaccessible
- `implementation_status`: reference_only / candidate / validated / pending
- `notes`, `reviewer`

링크가 접근 불가·삭제·리다이렉트인 경우 상태를 기록하고 다른 출처로 대체했다고 가장하지 않는다. 같은 카드에 구판·개정판·위키 해석이 함께 있으면 각각 별도 근거로 보존한다.

## 3. DB 데이터 구조 및 검토 규칙

1. **원문 보존:** 카드 원본 `TextBase`, `TextExtra` 및 원본 ID·URL은 변경 없이 보존한다. 정규화·OCR 결과는 별도 파생 필드에 저장한다.
2. **카드 정체성:** 이름만으로 카드를 병합하지 않는다. 카드 ID, 속성, 종류, 버전/발매시점, 원문을 함께 비교한다. OCR fuzzy 일치나 이름 충돌은 검토 큐에 넣는다.
3. **효과 구조:** 확인 가능한 범위에서 `effect`, `trigger`, `condition`, `target`, `amount/formula`, `duration`, `scope`, `cost`, `turn_phase`, `result/state`를 분리한다. 조건과 효과를 하나의 평문 필드에 뭉치지 않는다.
4. **참조·목록 효과:** 이름 나열, 기술명, 소환 카드 프로필, 영역/카운터 명칭은 그 자체로 실행 가능한 규칙이 아니다. 정의 문서·카드별 원문·엔진 근거를 연결하고 별도 확인한다.
5. **상충 근거:** 출처의 권위·시점·카드 ID 일치성을 비교한다. 해결되지 않으면 `pending_conflict`로 유지한다.
6. **실행 상태:** 근거가 불충분하거나 실행 검증 전이면 `semantic_review_status=pending` 및 `runtime_status=non_executable`을 유지한다. pending을 0으로 숨기거나 출처 문구만으로 executable로 바꾸지 않는다.
7. **근거 수준:** `source_text`(카드 원문), `official_or_primary`, `community_reference`, `inference`, `engine_observation`을 분리한다. 추론을 원작 사실처럼 기록하지 않는다.

## 4. 사용자 제공 카드 사례는 검토 큐이지 확정 사전이 아니다

사용자가 붙여준 나무위키 문단에 등장한 개별 카드(예: 레어, 인어의애정, 도깨비씨름, 뿌리침투, 색다른친구, 숲의지도자, 짙은안개, 폐허의흔적, 마력결계진, 석병팔진, 소르다스의검 등)는 카드별 후보 목록으로 보존한다. 설명에 기재된 비용·수치·상호작용은 해당 카드 ID 및 DB29 원문과 대조한 뒤에만 구조화한다. 전술적 평가·농담·당시 메타 설명은 카드 규칙 필드가 아니라 전략/주석 자료로 구분한다.

## 5. 후속 작업 순서

1. 참고자료 인덱스 작성: 나무위키 본문 및 관련 링크, 네이버 가이드, 관련 개인 사이트를 소스별로 등록하고 접근·추출 상태를 기록한다.
2. 카드별 매핑: 카드 ID 우선으로 자료를 매핑하고 OCR fuzzy/name collision을 별도 큐에 둔다.
3. 54행 pending effect 큐 처리: 23 named-effect 후보, 8 summon-profile 후보, 7 area-counter 후보 등 각 occurrence를 카드 원문과 정의 출처로 조사한다. 같은 이름이라고 일괄 확정하지 않는다.
4. 구조화 규칙 및 테스트: 효과/조건/대상/계산/지속/턴 구분이 보존되는지 집중 테스트한다.
5. Skill 26건 및 카드별 근거 누락 123건: 원문과 참고문서 링크를 보강한다.
6. Soul 831건: hybrid 52, NCS/BONUS 779의 원문·실제 지불 규칙을 각각 검토한다.
7. Engine 42건 및 매뉴얼 충돌 1건: APK 엔진/참고문서와 대조한다.
8. 데이터 배치가 실질적으로 완료된 뒤 집중 테스트, 그리고 전체 감사는 한 번 실행한다. 숫자는 최신 실행 산출물과 기준시점을 같이 표기한다.

위의 잔여 숫자는 기존 기준 수치이며, 새 전체 감사에서 재산출하기 전까지 완료량으로 갱신하지 않는다.

## 6. 버전 및 릴리스 통제

- DB29 immutable. 직접 덮어쓰기 금지.
- DB30은 데이터 변경·테스트·감사 및 사용자 확인 절차가 끝나기 전 발행 금지.
- PR은 작업 브랜치에서 작성하고 `main`에 자동/수동 병합하지 않는다.
- 외부 참고자료 반영은 소스 레지스트리와 데이터 diff를 함께 남긴다.
- Actions는 집중 검증을 우선한다. 이미지 전수검사·전체 감사·릴리스 workflow를 같은 작업 중 반복 실행하지 않는다.

## 7. 참고 문서의 사실 범위

초기 게임 소개 기사 및 보존 위키는 원작 기본 규칙과 용어의 참고용이다. 예를 들어 오래된 소개 문서는 7속성·4종류를 설명할 수 있지만, 후대의 인챈트/무속성 및 서비스 종료 전 패치와 다를 수 있다. 따라서 **규칙의 시점과 게임 버전**을 함께 기록하고 현재 데이터의 규칙으로 무조건 적용하지 않는다.
