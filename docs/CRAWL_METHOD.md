# 수집 방법 및 운영 정책

## 새 접근
이전 방식은 필드명/사이트 구조를 가정하는 기준으로 사용하지 않는다. Chromium으로 사이트를 실제 실행해 브라우저가 받는 JSON 응답, 페이지 이동, DOM, 링크, 이미지 주소를 관찰한다. 실제로 확인된 엔드포인트와 페이지네이션만 전용 어댑터로 채택한다.

## Probe 우선
사이트는 브라우저에서 JavaScript 실행이 필요한 앱으로 확인되었다. 최초 probe는 다음을 기록한다.
- 요청 URL/메서드/상태/콘텐츠 유형
- JSON 응답의 원본 파일
- 스크립트 주소, 링크, 버튼, 입력 요소, 이미지
- 페이지 제목 및 본문 텍스트
- DOM 구조 요약

probe만으로 카드가 15,350장 수집되었다고 간주하지 않는다.

## 전체 수집
- 요청 간격과 동시성을 낮게 유지하고 재시도/백오프를 적용한다.
- 브라우저에서 관찰된 정상적인 사이트 기능으로 페이지를 순회한다.
- JSON 응답 및 DOM에서 카드 레코드를 발견하면 ID 기준으로 중복 제거한다.
- 카드 상세 페이지를 확인할 수 있으면 개별 URL과 모든 상세 필드를 추가 수집한다.
- 이미지 원본 URL을 유지하고 파일 다운로드는 재시도 가능하게 한다.
- 중간 결과를 JSONL로 기록해 중단 후 이어서 수집할 수 있게 한다.
- 15,350장에 도달하지 못하면 완료 상태를 만들지 않고 누락 목록과 원인을 남긴다.

## 윤리·안정성
사이트 이용 조건과 robots 정책을 확인하고, 공개된 페이지에서 일반 사용자에게 제공되는 데이터만 수집한다. 로그인/접근통제를 우회하거나 서버에 과도한 부하를 주지 않는다. 차단 또는 오류가 발생하면 속도를 낮추고 중지/재시도한다.

## 데이터 산출
원본 JSONL은 변경하지 않는 원본 계층이다. SQLite는 이를 재구성 가능한 파생 산출물이다. 이미지 파일은 카드 ID로 이름을 만들고 원본 URL 및 해시와 연결한다.
